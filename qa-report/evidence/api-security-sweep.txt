# Checklist item 3 (IDOR, injection, SSRF, secrets). Related bugs: 003, 007, 008,

## 1. SQL injection
$ grep -rn '\$queryRaw\|\$executeRaw' apps/api/src --include='*.ts'
apps/api/src/modules/ports/ports.routes.ts:210:  countRes = await prisma.$queryRawUnsafe(countSql, ...params)
apps/api/src/modules/ports/ports.routes.ts:221:  rows = await prisma.$queryRawUnsafe(dataSql, ...params)
apps/api/src/modules/import-export/import-export.routes.ts:50:  $queryRawUnsafe('SELECT * FROM v_port_overview ORDER BY port ASC')

- ports.routes.ts: every user filter is pushed as a $N placeholder + params array
  (status/layer/protocol/q/process/server/tag/portMin/portMax); boolean filters are
  fixed literals. Dynamic sort goes through an allowlist map (ports.routes.ts:187
  `allowedSortFields`, :203 only interpolates allowlisted names).
- LIMIT/OFFSET interpolate `limit`/`page` which in the BASELINE have no zod bounds
  (BUG-021): z.coerce.number() still forces numeric input, so non-numeric strings
  cannot inject SQL — observed `?limit=Infinity` reaches Postgres as LIMIT NaN ->
  error 500 (proof below), not injection. Patch API-005 adds .int().min(1).max().
- import-export line 50 is a static constant string.
Conclusion: no SQLi found (parameterised + allowlisted).

## 2. Path parameter IDOR / traversal probes

{"error":"Route not found"} 404
$ curl -s -o - -w ' %{http_code}' 'http://127.0.0.1:3100/api/routes/../../etc/passwd'

  (Fastify normalises `../` before routing; handler sees literal id -> 404)
- Single-tenant schema: no per-object ownership column, so classic IDOR (cross-
  tenant object access) does not apply. Authorization is role-based only
  (admin/viewer, middleware/auth.ts) and is NOT enforced on baseline:
$ curl -s -o /dev/null -w '%{http_code}' 'http://127.0.0.1:3100/api/routes?limit=2'
200     <- unauthenticated data access succeeds => BUG-003 (auth gap), already
           covered by tests/api-auth.test.mjs (8 FAIL baseline).
Conclusion: no object-level IDOR beyond BUG-003.

## 4. SSRF
$ grep -rn "webhook\|slackDiscord\|telegram" apps/api/src --include='*.ts'  (settings)
  -> settings are stored (alerts.routes.ts:117-127) but NEVER read: no fetch/
     http.request/https.request anywhere in apps/api/src, no nodemailer/telegraf.
  -> alert channels never leave the process (BUG-052), so there is no
     attacker-controllable server-side request at all in the baseline.
- The scanner itself probes user-declared hosts (tcp/http checks) — that is the
  product's intended function, gated behind admin role by patch API-001.
- Host header: used by CORS/origin comparison only (app.ts), never as a fetch URL.
Conclusion: no SSRF beyond intended scanning; alert egress unimplemented (052).

## 5. Secrets / leakage
$ git ls-files | grep -i '\.env'          -> .env.example only (no real .env committed)
$ grep -rn "bcrypt" apps/api/src/modules/auth/*.ts
  -> import bcrypt from 'bcryptjs'; bcrypt.compareSync(password, user.passwordHash)
$ grep -rn "password" apps/api/src/modules/auth/*.ts | grep -i "log\|console"  -> none
  (no credential logging)
- Error leakage (BUG-013) — baseline has NO global error handler at all:
  $ grep -rn "setErrorHandler" apps/api/src  -> (no matches)
  $ curl -s 'http://127.0.0.1:3100/api/ports?limit=Infinity'

     "\nInvalid `prisma.$queryRawUnsafe()` invocation:\n\n\nRaw query failed.
     Code: `42703`. Message: `column \"nan\" does not exist`"}
  => full Prisma invocation + SQL state leaked to any client (pre-fix; API-001
     adds setErrorHandler returning a generic message).
- Auth secrets in responses: passwordHash returned by baseline user endpoints —
  BUG-003/010 family, patched by API-003 (response schema strips hash).
- Prod API docs exposed at /api/docs (Scalar) — BUG-048.
Conclusion: no new secret exposure; 013 leak above is live baseline evidence.
